bugs** — recorded here so they aren't re-raised:

- **Enter-to-search "doesn't submit"** (reported major, ×2 reviewers). The
  `onKeyDown` handler is correctly wired and its body works (direct invocation
  navigates). The in-app browser's synthetic key press delivers a keydown with
  `key === ""` (and the `"Enter"` variant delivers no event at all), so the
  `e.key === 'Enter'` guard can never match under automation. A real keyboard
  sends `key === "Enter"` and it works. **No fix needed.**
- **"+ filter button doesn't work on mobile"** (reported major). The builder
  works on desktop (chip added, URL updates). The mobile failure matches touch
  emulation not firing `click`; **likely artifact**. Cheap hardening available
  (`user-select: none` on buttons) but not a confirmed defect.
- **NULL contrast still failing** (reported minor by record-overview). Screenshot
  estimate; the computed color is `#6b7280` (**4.6:1**) from the earlier fix.
  **Already fixed.**

## Confirmed findings (most severe first)

### 1. `blocker` · responsiveness — Record page scrolls the whole body sideways on mobile
- **Flow/page:** record-overview · `/entities/<table>/<pk>` · mobile
- **Evidence:** At 375px, dragging right moves the header, breadcrumb, and all
  card headings *together with* the value column — page-level `<body>` scroll,
  not inner-container. The related-rows sub-tables scroll correctly inside their
  own box; the **Record** key/value panel doesn't. Long values (UUIDs, JSON)
  set the table's intrinsic width past the viewport.
- **Fix:** wrap the `.kv-table` in an `overflow-x:auto` container and/or
  `min-width:0` + `word-break:break-word` on the value `td`, and cap the label
  `th` width on mobile — mirror the `.data-table-wrap` pattern already used.

### 2. `major` · scaling — jsonb block widens the page on mobile
- **Flow/page:** record-overview · `documents.signatures/<pk>` · mobile
- **Evidence:** `.json-block` renders `white-space: pre`; on mobile its long
  lines aren't bounded by the cell, so scrolling to read them drags the whole
  page (same root cause as #1). Renders correctly (bounded box) at tablet/desktop.
- **Fix:** constrain the block to its cell width (the #1 wrapper fixes most of
  it); optionally `white-space: pre-wrap` below a breakpoint.

### 3. `major` · readability — long table names hard-clipped with no ellipsis or tooltip
- **Flow/page:** home · `/` · all viewports
- **Evidence:** 20 of 109 `.entity-name` nodes overflow; computed
  `text-overflow: clip` and the card clips the overflow, and names are single
  underscore tokens so they don't wrap. `compete.phase_bracket_progression_types`
  shows as `…progression_`; no `title` attr, so the full identifier is
  unrecoverable without navigating in. In a DB tool the exact name is load-bearing.
- **Fix:** `text-overflow: ellipsis` + a `title` with the full `schema.table`, or
  allow wrap (`overflow-wrap:anywhere`) onto a second line.

### 4. `major` · loading — no in-flight indicator while a query runs
- **Flow/page:** entity-list, empty-results · all
- **Evidence:** After committing a search/sort/filter, the stale table stays
  on-screen with no spinner/skeleton/dimming until the new rows replace it
  (~1–1.5s). Users get no acknowledgement the request was received.
- **Fix:** surface React Query's `isFetching` — dim the table or show a small
  spinner near the search box / a top progress bar while a page query is pending.

### 5. `minor` · accessibility — sortable headers lack `th[scope]` / `aria-sort` semantics
- **Evidence:** a11y tree shows header cells as generic wrappers around a
  "Sort by X" button; `aria-sort` only on the active column (others `undefined`),
  and the Record label column isn't `th[scope=row]`.
- **Fix:** ensure `<th scope="col">`, set `aria-sort="none"` on inactive sortable
  headers (not just the active one), and `<th scope="row">` for the Record keys.

### 6. `minor` · accessibility — every "view" link has the same accessible name
- **Fix:** `aria-label={`View ${pk}`}` (or the display value) on each row link.

### 7. `minor` · accessibility — empty/error states not announced; error page has no `h1`
- **Evidence:** "No rows found." and the "Unknown entity" error are plain
  generic nodes (no `role="status"`/`alert`); the error route has no heading.
- **Fix:** wrap the empty message in `role="status"`, the error in `role="alert"`,
  and give the error view an `h1`.

### 8. `minor` · usability — error state offers no recovery beyond the brand logo
- **Fix:** add a "Back to tables" link (or list valid schemas) on the error view.

### 9. `minor` · readability — related-entity cards repeat the full `where <col> = <uuid>`
- **Evidence:** all inbound-ref cards print the full parent UUID; at 375px this
  wraps 4–5 lines each, pushing content below the fold. The id is already shown
  at the top of the page.
- **Fix:** on narrow viewports truncate the id (`…a5e`) or drop the clause for a
  plain row count.

### 10. `minor` · themes — `prefers-color-scheme: dark` not honored
- **Fix:** declare `<meta name="color-scheme" content="light">` (documents the
  intent, keeps UA controls consistent) or add a dark token block — the palette
  is already centralized on `:root`.

### 11. `nit` · visibility — cards cap ~750px, leaving wide desktops half-empty
- **Fix:** raise max-width or a two-column layout for the record view. Low priority.
