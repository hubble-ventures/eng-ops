## Findings

### 🔴 Blockers

#### B-1 · responsiveness · `record-overview` — Long FK badge in the References card forces the whole page to scroll horizontally
- **Where:** `/entities/<table>/<pk>` References card, any record whose outbound FK resolves to a long display label. Reproduced on `documents.signatures`. Desktop **and** mobile, both themes.
- **Evidence (verified by measurement):** The `document_version_id` badge renders `documents/6dc2c319-…/Athletic_Participation_Agreement_and_Liability_Release-1…` in a `font-mono` `Badge` with `white-space: nowrap` and no `min-width:0`/truncate. Measured badge width **1187px**. At 1440px viewport `documentElement.scrollWidth = 1547 > clientWidth 1440` (**107px** page overflow); at a 576px pane, overflow was **651px**. Records with short FK values (e.g. `compete.competitions`) do **not** overflow, so the trigger is any long FK label. The same value inside the *Record* key/value table wraps fine — only the References badge blows out.
- **Source:** `src/routes/entities/$table/$pk.tsx` (References `<Badge variant="outline" className="… font-mono">`) + `src/components/ui/badge.tsx` (`whitespace-nowrap`).
- **Recommendation:** Cap the badge to the card width and let long values truncate or wrap: add `min-w-0 max-w-full` to the badge and `truncate` (or `break-all`) to its value span, so a single pill can never exceed the container.

#### B-2 · responsiveness · `record-overview` (and any record) — Tablet header overflows; long breadcrumb doesn't truncate, body scrolls sideways
- **Where:** ~`768px` (sidebar visible, narrow content column) on any page with a long breadcrumb — record pages, whose breadcrumb is `<table> / <pk>`. Both themes. Not present at desktop (room) or mobile (sidebar + breadcrumb hidden, search collapses to an icon).
- **Evidence (verified by measurement):** At 768px the breadcrumb `compete.competitions / ccd10cf1-5402-4cad-95d3-29c94b715bbb` measured **450px** wide and did **not** truncate, pushing the "Search tables…" button to `right = 858`, past the 768 viewport. `documentElement.scrollWidth = 858 > clientWidth 768` and `window.scrollTo(9999,0)` yielded `scrollX = 90` — the page body genuinely scrolls ~90px horizontally.
- **Root cause (source-confirmed):** In `src/routes/__root.tsx` the breadcrumb is wrapped in `<div className="hidden md:block">` — this flex child has **no `min-w-0`**, so the `truncate` on the inner breadcrumb spans never engages.
- **Recommendation:** Add `min-w-0` (and `overflow-hidden`) to the breadcrumb wrapper `div`, and give the search button `shrink-0` so the breadcrumb absorbs the squeeze and truncates instead of overflowing.

### 🟠 Majors

#### M-1 · visibility · `empty-results` / `entity-list` — Zero-result message renders but is positioned off-screen on wide tables
- **Where:** Any table wide enough to horizontally scroll. Confirmed on `compete.competitions` (17 columns). Desktop, both themes.
- **Evidence (verified by measurement):** After a no-match search the tbody **does** contain one row — `<td colspan="17">` with text `No rows match your search.` (so the DOM is *not* empty). But the cell is `text-center` spanning the full **2710px** table width, while the horizontal scroll container is only **1134px** wide (`scrollLeft 0`, visible range x≈281–1415). The centered text box measured **x = 1546–1726 → entirely off-screen right**. Screenshot shows a visually blank body under "0 rows / Page 1 / 1". (On an 11-column table the same message stays visible — the defect scales with column count.)
- **Source:** `src/components/DataTable.tsx` empty-row `<TableCell colSpan={… + 1} className="… text-center">`.
- **Recommendation:** Pin the empty state to the viewport, not the table width — render it outside the horizontally-scrolling table, or wrap the cell content in a `position: sticky; left: 0` element sized to the scroll container's `clientWidth`, so it's always visible at `scrollLeft 0`.

#### M-2 · accessibility · `entity-list` — Sortable headers never expose `aria-sort`; `th` cells lack `scope`
- **Where:** Data table, all viewports/themes.
- **Evidence:** After clicking the `name` header the sort applied correctly (URL `?sort=name&dir=asc`, arrow, rows reordered), but the `th` and its inner sort `<button>` both report `aria-sort = null` before and after; all 17 `<th>` report `scope = null`. Sort state and column association are not announced to assistive tech.
- **Source:** `src/components/DataTable.tsx` `TableHead` / sort `<button>`.
- **Recommendation:** Set `aria-sort="ascending|descending|none"` on the active header and add `scope="col"` to header cells.

#### M-3 · accessibility · `entity-list` — Pagination prev/next buttons have no accessible name
- **Where:** Pagination footer, all viewports/themes.
- **Evidence:** Both chevron buttons are icon-only (`size="icon"`), `aria-label = null`, `title = null`, no text; 32×32 desktop and mobile. A screen-reader user hears only "button" with no previous/next distinction.
- **Source:** `src/components/DataTable.tsx` (`<Button variant="outline" size="icon">` with `<ChevronLeft/>` / `<ChevronRight/>`).
- **Recommendation:** Add `aria-label="Previous page"` / `"Next page"` (or visually-hidden text).

#### M-4 · accessibility · `entity-list` — On mobile the "Columns" and header table-search buttons collapse to icon-only with no name
- **Where:** `375px` (both themes). At desktop these show visible text, so the name is lost only in the collapsed layout.
- **Evidence:** At 375px the toolbar "Columns" button (`aria-label=null`, `title=null`) and the header search toggle (`aria-label=null`, `title=null`) are icon-only. Their labels are `<span className="hidden sm:inline">` / `hidden sm:inline`, hidden below `sm`. (The density toggle is fine — it has `title="Comfortable rows"`.)
- **Source:** `src/components/DataTable.tsx` (Columns trigger), `src/routes/__root.tsx` (header search button).
- **Recommendation:** Add an `aria-label` to both buttons so the icon-only mobile variants keep a name.

#### M-5 · accessibility · all flows — Mobile touch targets below the 44px minimum
- **Where:** `375px`, all flows/themes.
- **Evidence (measured `getBoundingClientRect`):** row `⋯` actions button **28×28** (the primary per-row control, worst offender), pagination chevrons **32×32**, header hamburger **36×36**, toolbar density/Columns **38×32**, header search toggle **38×30**. All clear the 24px floor but fall short of the 44px target.
- **Recommendation:** Give mobile icon buttons `min-h-11 min-w-11` (or padded transparent hit area) — especially the row `⋯` menu.

#### M-6 · readability · `home` — Entity card titles truncate with no tooltip, so similarly-named tables are indistinguishable
- **Where:** `home` card grid; worst at tablet (2-col), also desktop. Both themes.
- **Evidence (measured):** Title span is `truncate font-mono` with **no `title` attribute** (`anyTitle=false`). At 768px, **71/110** titles overflow their 168px column; `compete.competition_participants` and `compete.competition_sub_requests` both render as `compete.competition_…` — visually identical with no way to recover the full name. (5/110 also truncate at 1440px.)
- **Source:** `src/routes/index.tsx` card title span.
- **Recommendation:** Add a `title` (or tooltip) with the full `schema.table`, and/or truncate the schema prefix rather than the table name (or allow the name to wrap to a second line).

#### M-7 · usability · `record-overview` — jsonb and long text are not expandable; single-line ellipsis with only a raw title tooltip
- **Where:** Record detail (and cells generally), all viewports/themes.
- **Evidence (source + screenshot):** `CellValue` has **no special case** for objects/JSON or long strings — the fallthrough is `<span className="block max-w-[28rem] truncate" title={len>60 ? text : undefined}>`. A 755-char `field_values` jsonb value renders as one clipped line (`{"05042cb9-…`), no pretty-print, no scroll container, no expand button — the full value is reachable only via an unformatted native `title` tooltip. Long `consent_text` behaves the same. This is exactly the "scrollable pretty-printed JSON" the manifest expected and the app does not provide (manifest updated to reflect reality — see below).
- **Source:** `src/components/CellValue.tsx`.
- **Recommendation:** Detect jsonb/long values and render them expandably — a pretty-printed `<pre>` in a `max-height; overflow:auto` block, or a click-to-expand row — rather than nowrap-ellipsis with a raw tooltip.

#### M-8 · readability · `record-overview` — Record key/value grid stays 2-column at tablet, squeezing values to ~27px
- **Where:** `768px` Record card, both themes. Desktop renders fine (full-width values); mobile collapses to one column correctly — only the tablet breakpoint breaks.
- **Evidence (measured):** With the 256px sidebar present, the `dl` computed `grid-template-columns: 195px 195px`, leaving each value cell only ~27px: `id` shows `2…`, `name` shows `To…`, and `event_id` wraps one-glyph-per-line into a ~400px-tall column.
- **Source:** `src/routes/entities/$table/$pk.tsx` Record `dl` uses `sm:grid-cols-2`, which triggers at 640px regardless of the sidebar-reduced content width.
- **Recommendation:** Make the grid responsive to actual content width (e.g. stay `grid-cols-1` while the sidebar is shown at tablet, or use container queries), and give value cells a sensible `min-width`.

### 🟡 Minors

#### m-1 · colors · `record-overview` — NULL placeholder fails WCAG AA contrast
- **Evidence:** `CellValue` renders NULL as `text-muted-foreground/60 italic` at 12px. Sampled **#ababab on white = 2.30:1** (light, fails even the 3:1 large floor) and **~3.31:1** (dark) — below the 4.5:1 bar for this small text. NULL conveys real state, so it should stay legible.
- **Recommendation:** Drop the `/60` opacity (use full `muted-foreground`) or raise the token so NULL clears 4.5:1.

#### m-2 · usability · `record-overview` — Booleans render as blue link-colored text, not pills
- **Evidence:** `CellValue` returns `<span className="text-link font-mono">true|false</span>` — same link-blue as clickable FK values, no pill/background, no true-vs-false color or icon. They read as clickable links but are inert, and `true`/`false` are visually undifferentiated.
- **Recommendation:** Render booleans as non-link badges (e.g. `true`=green/check, `false`=muted/x) distinct from FK links.

#### m-3 · readability · `error-state` — Light-theme error/destructive text below AA (3.98:1)
- **Evidence:** "Unknown entity: …" renders `text-destructive` `rgb(231,0,11)` on `bg-destructive/10` `rgb(253,229,231)` = **3.98:1** at 14px (dark theme is fine at 6.66:1). This token drives every destructive/validation message, so the miss is app-wide in light mode.
- **Recommendation:** Darken the light-mode destructive foreground token so error copy on the tinted panel clears 4.5:1.

#### m-4 · usability · `empty-results` — Zero-result state is terse
- **Evidence:** Only copy is `No rows match your search.` — no icon, no echo of the query, no recovery hint beyond the input's small `×`.
- **Recommendation:** Add a small icon and an actionable line (e.g. `No rows match "zzzqqq". Clear the search or try another term.`). (Fix M-1's positioning first, or users won't see this at all.)

#### m-5 · usability · `error-state` — Error panel has no inline recovery action
- **Evidence:** The main panel shows only the styled message (a plain `<div>`, not a heading) with no "Back to tables"/"Home" link; recovery depends entirely on the persistent sidebar/home link remaining visible.
- **Recommendation:** Add an inline "Browse tables" link and promote the message to a heading so the error is self-contained.

#### m-6 · accessibility · `home` — Mobile nav drawer lacks dialog semantics
- **Evidence:** The hamburger reports `aria-expanded=null`/`aria-haspopup=null`; the opened full-screen menu (`div.fixed.inset-0.z-50`) has `role=null`/`aria-modal=null` and no focus trap. It has an accessible-named Close button, but SR users get no expanded/modal signal.
- **Source:** `src/routes/__root.tsx` mobile drawer.
- **Recommendation:** Add `aria-expanded`/`aria-controls` to the trigger, `role="dialog" aria-modal="true"` + an accessible name to the overlay, and trap focus while open.

#### m-7 · loading · all flows — Console throws React "Invalid hook call" + null `useEffect` on every load *(dev build)*
- **Evidence:** `read_console_messages(onlyErrors)` on a clean load returns 2× `Invalid hook call…` and `Uncaught TypeError: Cannot read properties of null (reading 'useEffect')` from `.vite/deps/react-dom_client.js`, on every navigation. The app still renders and functions.
- **Attribution (source-confirmed):** `src/routes/__root.tsx` mounts `<TanStackRouterDevtools>` and `<ReactQueryDevtools>` **unconditionally**; this is the classic "more than one copy of React" / devtools symptom in a **dev** build. It most likely does **not** affect a production build (these devtools self-gate on `NODE_ENV`), so this is scoped as a dev-time issue — but uncaught errors on load can mask real failures and should be cleaned up.
- **Recommendation:** Gate the devtools behind `import.meta.env.DEV` (and/or resolve the duplicate-React so the console is clean). Re-audit `loading` against a production build to confirm no user-facing impact.

### ⚪ Nits

#### n-1 · colors · `home` — `⌘K` search hint below AA
- **Evidence:** The `kbd` `⌘K` hint computes to `oklch(0.556 0 0)` on `oklch(0.97 0 0)` = **4.34:1** at 10px (just under 4.5:1). Secondary, but small.
- **Recommendation:** Darken the `kbd` text (e.g. `foreground/70`) or enlarge slightly.

## Top fixes (highest leverage)

1. **Stop long FK badges from blowing out the page (B-1)** — one `min-w-0 max-w-full` + `truncate` on the References badge kills a page-level horizontal-scroll blocker on every record with a long FK label.
2. **Truncate the breadcrumb at tablet (B-2)** — add `min-w-0` to the breadcrumb wrapper `div` (+ `shrink-0` on the search button). Removes the second h-scroll blocker.
3. **Make the empty-state message viewport-pinned (M-1)** — sticky/`left:0` (or move it out of the scrolling table). Today wide tables look broken on a no-match search.
4. **Data-table a11y pass (M-2..M-5)** — `aria-sort` + `scope="col"`, `aria-label` on pagination and mobile Columns/search buttons, and `min-h-11/min-w-11` on mobile icon buttons. Small, mechanical, high coverage.
5. **Rich-value rendering on the detail page (M-7, m-1, m-2)** — expandable/pretty-printed jsonb & long text, a readable NULL token, and boolean pills — the record view is where users go for the *full* value and currently can't get it.

## Verification notes — false positives caught this run

Because this was the first real run, candidate findings were re-checked before landing here. Two were **dropped**:

- **"App ignores `prefers-color-scheme`, always loads light" (themes) — DROPPED (false).** `src/components/ThemeToggle.tsx` `themeInitScript` is `if (t==='dark' || (!t && m)) document.documentElement.classList.add('dark')` — it **does** honor the system preference on a clean load. The reviewer's observation was contaminated by an earlier reviewer clicking the theme toggle, which persisted `theme` in `localStorage` and pinned subsequent loads. Verified by reading source and by the app loading dark by default under a dark system scheme with no stored theme.
- **"Empty search shows a blank table body, no message" (usability) — CORRECTED, not dropped.** The message *is* in the DOM; it's positioned off-screen on wide tables. Re-filed accurately as **M-1 (visibility)** with measured coordinates.

The known automation caveat (the in-app browser's synthetic Enter can arrive as an empty key) did **not** produce any false "Enter doesn't submit" finding — the app's search is intentionally debounced with no submit, and reviewers were instructed accordingly.

## Manifest corrections applied to `flows.jsonc`

This first real run revealed the manifest (authored against an older orphaned build) described UI that doesn't exist. Corrections committed alongside this report:

- **`entity-list`:** search is **debounced (~300ms), no submit/Enter** (was "type … and submit"); the toolbar is **Search + density "Compact" + "Columns" dropdown** (there is **no filter bar / per-column value filters** — replaced that step with the real column show/hide toggle); pagination is a next-chevron button. Flow name updated to "table, sort, search, columns, pagination".
- **`record-overview`:** rows open by **clicking the row itself** (no separate "view" link; the `⋯` is row actions) (was "click a row's 'view' link"); the FK card is titled **"References"** (was "Links pills"). Kept the jsonb/long-text check — the app *fails* it (M-7), which is a real finding, not a manifest error.
- **`home`:** added the **persistent left sidebar (schema tree)** to what's observed and its mobile behavior (it correctly collapses to a hamburger drawer — no finding).

Routes confirmed as `/entities/$table` and `/entities/$table/$pk` with search params (`page`, `pageSize`, `sort`, `dir`, `q` on the list; `pkColumn` on the record). The manifest's query-string paths match the real router.
